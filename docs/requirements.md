# arsApps 要件定義（たたき台）

## 1. 前提
- 利用者：事務所内勤 約4名（社員5〜10名以下）、業務委託ドライバー30〜40名（ドライバーはアプリを使わない想定）
- PC・スマホのブラウザから利用
- 初期費用・ランニングコストを最小限にする

## 2. 推奨構成（本番）
| 項目 | 推奨 | 費用目安 |
|---|---|---|
| 画面 | React + Vite（本サンプルをそのまま発展） | 0円 |
| ホスティング | Vercel / Cloudflare Pages（無料枠） | 0円 |
| DB・認証 | Supabase（PostgreSQL + Auth、無料枠） | 0円〜（安定運用なら Pro 月$25） |
| Excel出力 | SheetJS（ブラウザ内で生成） | 0円 |

- 4名・数千件/年規模なら無料枠で十分。Supabase 無料枠は1週間アクセスがないと一時停止するため、業務で毎日使うなら問題ないが、確実性を求めるなら Pro を検討。
- セキュリティ：Supabase Auth のメール+パスワード認証、新規登録は無効化し管理者が招待。全テーブルに RLS（行レベルセキュリティ）を設定し、ログインユーザー以外は読み書き不可。通信は HTTPS。

## 3. 機能一覧
### 3.1 共通
- ログイン/ログアウト、トップページ（各機能へのリンク＋ダッシュボード）

### 3.2 案件予定表（サンプル実装済み）
- 縦軸ドライバー・横軸日付の1週間表示、前週/次週/日付ジャンプ
- 1行目に「担当者未定」行
- 委託会社は会社単位の行にまとめ、カードに個人名を表示
- 「常時表示しない」ドライバーは、その週に案件がある場合のみ表示（全表示切替あり）
- 案件カードはドラッグで日付・担当変更（Ctrl/Option+ドラッグでコピー）、請求先ごとに色分け
- 日付クリックでその日の一覧
- 案件登録：担当者、積み地/降ろし地（複数可）、台数、請求先、定期（毎日/平日/毎週＋終了日）、備考、請求額/支払額
- 定期案件は1日1件の実体として生成し、シリーズIDで紐付け。編集・削除時に「この日のみ / この日以降すべて」を選択
- 基本割り当て（毎日固定の担当）登録
- 休暇登録（期間指定）

### 3.3 ドライバー管理（サンプル実装済み）
- フルネーム、読み仮名、電話番号、表示名、区分（個人/所属会社/自社正社員）、所属会社、予定表常時表示の可否
- ドライバー画面から案件作成

### 3.4 請求・支払管理（サンプル実装済み・要検討）
- 案件カード1件＝請求1明細・支払1明細として紐付け（案件に請求額・支払額を保持）
- 月次で請求先別・支払先別（所属会社ドライバーは会社単位）に集計
- 明細画面で金額を直接編集
- Excel出力（明細／請求先別／支払先別／請求先ごとの請求書下書きシート）、印刷・PDF

### 3.5 車両管理（サンプル実装済み）
- 車名、ナンバー、車検満了日、貸出先、最終使用日、修理履歴（日付・内容・費用）
- トップに車両ダッシュボード、車検60日以内を警告、30日以内を赤表示

## 4. 請求・支払管理についての助言
1. **金額の基本は「請求先ごとの単価マスタ」から自動入力**し、案件ごとに上書きできるようにする（例：〇〇物流 都内ルート＝25,000円）。毎回の手入力を減らせる。
2. **案件に紐付かない金額（高速代、待機料、燃料サーチャージ、値引きなど）は「追加明細」として案件または月単位に別行で持つ**。カードに無い金額はここで吸収し、Excel出力後の手修正を最小限にする。
3. **月次で「締め」を行い、締め後は金額をロック**（変更は管理者のみ・履歴を残す）。請求書発行後に予定表側を動かしても請求額がずれないようにする。
4. **インボイス制度対応**：支払先（個人ドライバー）ごとに適格請求書発行事業者かどうか・登録番号を持たせ、免税事業者の場合の仕入税額控除の経過措置を考慮した集計ができるようにする。源泉徴収の要否も確認が必要。
5. 請求書の正式な帳票（PDF）はテンプレートを1つ決めて実装し、例外的なものは Excel 出力で対応する、の二段構えにすると開発コストを抑えられる。
