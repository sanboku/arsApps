# arsApps 要件定義（たたき台）

## 1. 前提
- 利用者：事務所内勤 約4名（社員5〜10名以下）、業務委託ドライバー30〜40名（ドライバーはアプリを使わない想定）
- PC・スマホのブラウザから利用
- 初期費用・ランニングコストを最小限にする

## 2. 推奨構成（本番）
| 項目 | 推奨 | 費用目安 |
|---|---|---|
| 画面 | React + Vite（本サンプルをそのまま発展） | 0円 |
| ホスティング | Vercel / Cloudflare Pages（無料枠） | 0円 |
| DB・認証 | Supabase（PostgreSQL + Auth、無料枠） | 0円〜（安定運用なら Pro 月$25） |
| Excel出力 | SheetJS（ブラウザ内で生成） | 0円 |

- 4名・数千件/年規模なら無料枠で十分。Supabase 無料枠は1週間アクセスがないと一時停止するため、業務で毎日使うなら問題ないが、確実性を求めるなら Pro を検討。
- セキュリティ：Supabase Auth のメール+パスワード認証、新規登録は無効化し管理者が招待。全テーブルに RLS（行レベルセキュリティ）を設定し、ログインユーザー以外は読み書き不可。通信は HTTPS。

## 3. 機能一覧
### 3.1 共通
- ログイン/ログアウト、トップページ（各機能へのリンク＋ダッシュボード）

### 3.2 案件予定表（サンプル実装済み）
- 週表示／月表示の切替、前後移動、「今日」ボタン（今日の列まで自動スクロール）、日付ジャンプ
- 縦軸ドライバー・横軸日付。各ドライバーは「AM」「PM」の2段で表示（積み時間12:00以降＝PM、時間未設定はAM）
- ドライバー名は改行せず1行表示（長い名前は省略、マウスを乗せると全体表示）。名前横の「＋」でその担当の案件を追加
- 各段の中は時間の早い順に並べる
- 1行目に「担当者未定」行
- 行の並び順はドライバー管理画面の「予定表の表示順」で変更可能（会社内のドライバーの並びも変更可）。予定表上部の「↕ 表示順を変更」から移動できる
- 社員はドライバー欄に表示中の月の休暇日数（通常休暇・希望休別）を表示
- 案件の検索：キーワード（積み地・降ろし地・備考・請求先・担当者・メモ）＋担当者・請求先・種類・期間で絞り込み。結果一覧から該当日へ移動、予定表では非該当カードを薄く表示
- 委託会社は会社単位の行にまとめ、カードに個人名を表示。所属ドライバーごとに「独立した行で表示」を設定でき、その人は会社の行とは別の行になる
- 「常時表示しない」ドライバーは、その範囲に案件がある場合のみ表示（全表示切替あり）
- 祝日は日付見出しを赤字＋祝日名で表示
- 案件カード：請求先は表示せず色で区別（1行表示）。色はカードごとに指定可能（指定なしは請求先の色）。カーソルは指差しの形。週表示は「積み地 → 降ろし地」、降ろし地が空なら業務名のみ。月表示は積み地のみ
- ドラッグで日付・担当変更（Ctrl/Option+ドラッグでコピー）、日付クリックでその日の一覧（時間順）
- 案件登録：担当者、積み地/降ろし地（複数可・降ろし地は空欄可）、積み時間/降ろし時間、台数、請求先、備考、請求額/支払額
- 繰り返し：単発／定期案件（🔁）／固定業務（📌）。頻度は毎日／曜日選択（月〜日を選択、毎週・隔週・開始週のみ）、終了日（空欄なら1年先まで作成）。祝日も稼働するかを選択（オフなら祝日はカードを作らない）
- 繰り返しは1日1件の実体として生成し、シリーズIDで紐付け。編集・削除時に「この日のみ / この日以降すべて」を選択
- 編集画面でも繰り返し設定を変更可能。種類（固定⇔定期）だけの変更はシリーズ全体のラベルを変更、頻度・曜日・終了日・単発化の変更はその日より後のカードを作り直す
- メモカード（📝）：案件とは別のメモ。日付・担当者（未定可）・時間（任意）・内容・色。ドラッグで移動・コピー可。請求には含まれない
- 複数台案件：台数分のカードを作成し、グループIDで紐付け。カードに「🚚2/3」（2台目/全3台）を表示、マウスを乗せると同じ案件の車両を強調。編集画面で各車両の担当者変更・1台追加・この車両のみ削除／全台削除。請求先・場所・時間・備考の変更は全車両に反映
- 固定業務登録（毎日固定の担当）：繰り返し＝固定業務、曜日選択（月〜金）を初期値として開く
- 休暇：通常休暇／希望休の2種類。予定表のマス・「＋」・「案件・休暇登録」から開く登録画面のタブで選び、期間指定で登録。案件が割り振られている日・すでに休暇がある日は登録不可。休暇日への案件割り当ては確認を出す。休暇の札はドラッグで移動、Ctrl/Option＋ドラッグでコピー（同じ制約あり、担当者未定の行には不可）
- 案件登録・編集画面はPC（1366x768以上）でスクロールなしで収まる2列レイアウト

### 3.3 ドライバー管理（サンプル実装済み）
- フルネーム、読み仮名、電話番号、表示名、区分（個人/所属会社/自社正社員）、所属会社、予定表常時表示の可否
- ドライバー画面から案件作成

### 3.4 請求・支払管理（サンプル実装済み）
- **管理表**：案件カード1件＝管理表の1行（同じデータ）。カード追加で行が増え、管理表で直した距離・請求額・支払額はカードにも反映
  - 列：日付／担当者／所属（＝支払先。所属会社は会社略称、個人委託は「個人」、自社正社員は「自社」）／内容／距離(km)／立替金／請求先／請求額／支払額／利益率
  - 立替金：高速代などの税込実費。請求・支払の両方に同額を消費税なしで計上（利益率の計算には含めない）。案件カードにも入力欄あり
  - 請求先・支払先で絞り込み、担当者未定・請求先未設定・請求額0円を警告表示、Excel出力
- **略称と正式名称**：画面（カード・管理表）は略称、帳票は正式名称・敬称・郵便番号・住所（請求先・委託会社に保持。個人委託はフルネーム＋住所）
- **月末の締め**：締めた月の案件は登録・変更・削除・移動不可（予定表・管理表とも）。締め解除で再編集可能
- **帳票**：請求先ごとの請求書・支払先ごとの支払明細書を管理表から作成（締め前でも作成可。作成時の合計を保持し、その後管理表が変わったら一覧で警告）。固定業務・定期案件は同じシリーズ・同額・同内容をまとめて「期間・回数 × 単価」の1行に。列は 日付／内容／立替金（税込）／金額（税抜）、合計＝小計＋消費税（小計のみ課税）＋立替金。A4の見た目のまま全項目を編集可能（行の追加・削除で高速代などに対応）、編集内容は保存。小計・消費税（自社情報の税率、帳票ごとに「消費税なし」可）・合計を自動計算。番号は YYYYMM-S/P連番。印刷・PDF保存（ブラウザの印刷機能）、Excel出力。「管理表から作り直す」で再作成
- **単価マスタ**：名称・請求先・適用期間・請求額・標準支払額・支払先ごとの支払額・標準距離。案件で選ぶと金額・距離を自動入力し、担当者変更（ドラッグ含む）時は支払先に応じた支払額に自動更新。自社正社員の支払額は0
- **支払先別の集計**：支払額に加えて売上（請求額）・利益率を表示。自社正社員は支払対象外だが1人ずつ売上を集計し合計も表示
- **自社情報**：会社名・住所・電話・登録番号・振込先・消費税率（帳票の発行元）

### 3.5 車両管理（サンプル実装済み）
- 車名、ナンバー、車検満了日、貸出先、最終使用日、修理履歴（日付・内容・費用）
- トップに車両ダッシュボード、車検60日以内を警告、30日以内を赤表示

## 4. 請求・支払管理についての助言
1. **金額の基本は「単価マスタ」から自動入力**し、案件ごとに上書きできるようにする。→ 実装済み
2. **案件に紐付かない金額（高速代、待機料、燃料サーチャージ、値引きなど）** → 現状は帳票の「行を追加」で対応。頻繁に発生するなら、案件カードに「追加費用」欄を設けて管理表にも出す
3. **月次で「締め」を行い、締め後は金額をロック** → 実装済み。本番では締め・解除を管理者のみに制限し、操作履歴を残す
4. **インボイス制度対応**：支払先（個人ドライバー）ごとに適格請求書発行事業者かどうか・登録番号を持たせ、免税事業者の場合の仕入税額控除の経過措置を考慮した集計ができるようにする。源泉徴収の要否も確認が必要。
5. 請求書の正式な帳票（PDF）はテンプレートを1つ決めて実装し、例外的なものは Excel 出力で対応する、の二段構えにすると開発コストを抑えられる。

6. **距離の入力方法**：当面は管理表で手入力＋単価マスタ／定期案件の標準距離で自動入力。将来的には、積み地・降ろし地を正確な住所で登録すれば、Google マップの経路API等で自動計算できる（APIキーと少額の従量課金が必要。小規模なら無料枠内に収まる可能性が高いが、料金体系は導入時に要確認）。走行距離を実測で管理したい場合は、ドライバーの日報（メーター値）を取り込む方式も検討
